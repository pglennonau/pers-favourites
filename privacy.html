Pers Favourites — Privacy Policy

Version 0.27.23 · Effective 20 September 2026

This policy describes the data handling of the current Pers Favourites release. The current catalogue is primarily stored on the user's device. Cloudflare is used as the service layer for authorised external connections.

Local app data

The current release stores collection data, preferences, ratings and locally contributed photos in browser/device storage. Clearing site data or removing the app may remove this local information unless it has been backed up.

Location

If the user permits location access, Pers may use the device's current coordinates to find nearby places and calculate distance. Location is requested through the browser/device permission system. When a user performs an external place search, relevant search and location context may be sent through the Pers Cloudflare service to the selected provider.

Google Maps Platform

When Google Maps features are used, Google may process search requests, location context and related service data under the Google Privacy Policy. Pers does not store Google photo resource names or live Google ratings/opening status as permanent Pers catalogue data. Google Place IDs may be retained where permitted for identifying a place.

Tripadvisor

When Tripadvisor API features are enabled and deliberately used, relevant search context is sent through the Pers Cloudflare service to Tripadvisor. Live Tripadvisor provider content is kept source-specific. API usage is subject to configured quota and cost safeguards.

Cloudflare and other services

Cloudflare processes requests used to operate the Pers service layer. If Ask Pers is enabled in a future connected configuration, relevant user queries may be sent through a protected service to the configured AI provider. Secret API keys are kept server-side and are not placed in the PWA or browser storage.

Payments

Pers does not store full payment-card numbers or security codes. Billing and payment details remain with the relevant external provider. The Owner view may show non-sensitive service status, usage, spending controls or masked payment metadata when an authorised provider interface makes that information available.

User contributions

Where photo contribution is enabled, contributor identity information may be requested at the point of contribution so submissions can be managed and moderated. In the current local-data release, photos are stored locally; future shared storage will use Cloudflare-based services and this policy will be updated before deployment.

Changes

This policy is updated when the application architecture or connected services materially change. The version and effective date above identify the policy supplied with this release.
